                  기본 켜짐이지만 저장한 규칙이 없으면 자동으로 답하지 않습니다. 같은 PC 사용자·프로젝트 폴더·요청·질문 또는 명세·시안이 정확히 같을 때만 재사용합니다. 권한·새 외부 대상·비판 검증 질문은 항상 직접 확인합니다.
                    GitHub·Vercel 반복 전송 정책은 이 프로젝트의 보조 서비스 설정에서 관리합니다. 자동 수락을 끄면 다음 전송부터 다시 묻습니다.
                    
    
                    개발 서버·상태별 프리뷰

                    최대 6개. id, path, width, height, selector(컴포넌트 CSS), actions의 click/fill/select와 selector/value를 지정합니다. 계정·비밀값·파일 입력은 사용하지 마세요.

                    FIRST-RUN TOOL CHECK
                    작업 전에 공구함을 확인해요
                    
      
                    필수 프로그램을 모두 준비해야 AI 작업과 앱 제작을 시작할 수 있습니다. 필수는 현재 선택한 AI·실행 방식에 필요한 도구이고, 선택은 없어도 작업을 시작할 수 있습니다. 설치 전에는 설정·계정 연결·작업 기록을 확인할 수 있어요. 로그인 여부는 ‘계정 · 연결’에서 확인하세요.
                    
      
                    
      
                    
      
                    설치 버튼은 공식 안내를 기본 브라우저에서 엽니다. 설치 파일이나 원격 스크립트를 자동 실행하지 않습니다. Docker 실행에는 엔진과 로컬 이미지 준비도 필요합니다.
                    
      
                    기본 격리 이미지는 Docker를 실행한 뒤 터미널에서 docker pull node:24-bookworm-slim으로 준비합니다. 의존성이 필요한 프로젝트는 준비한 별도 이미지를 설정에서 지정하세요.

                    WORKSPACE SETTINGS
                    
            
                    작업 환경 설정
                    
            
                    
              변경 사항은 다음 작업부터 적용됩니다.
            
                    
          
                    
          
        
                    
        
                    
          
                    
            
                    작업 자동화
                    
            
                    
              
              
              
              
              
                    승인한 이미지가 있는 UI 작업에 적용합니다. 기능 테스트와 별도로 UI 담당 AI가 비교하며, 차이가 남으면 기존 자동 수정·호출 한도 안에서 보정합니다. 캡처·이미지 입력이 불가능하면 확인 필요로 멈춥니다.
                    
              
              
              
              
              
              
              
              
              
              
              
              
                    
              
                    동시 요청도 호출 전에 횟수와 비용을 예약합니다. 비용은 입력 바이트·최대 출력 토큰·설정 단가에 따른 보수적 추정이며 공급자 청구 상한을 보증하지 않습니다. 비용 예산을 켜면 단가를 확인할 수 없는 이미지 입력·생성을 차단합니다. CLI 구독의 잔여 토큰은 공급자 한도를 따릅니다.
                    
              
            
                    
            
                    
              테스트 역할 선택 시 명세의 시나리오를 실제 테스트 코드와
              연결합니다. 기본 실행기는 Node.js 내장 테스트이며 패키지를 자동
              설치하지 않습니다. npm 스크립트는 해당 실행기를 선택했을 때
              사용합니다.
            
                    
          
                    
          
                    
            
                    권한과 실행
                    
            
            
            
            
                    격리 실행은 비밀 파일·로그인을 제외한 복사본을 읽기 전용으로 전달합니다. 인터넷과 호스트 쓰기 마운트는 없고 결과 보고서만 제한해 가져옵니다. 의존성은 자동 설치하지 않으며, 필요한 경우 /opt/node_modules를 준비한 별도 이미지를 지정하세요.
                    
            
                    
              
            
                    
            
                    
            
                    
              테스트·검증 코드는 현재 PC 사용자 권한으로 실행됩니다. 신뢰하는
              프로젝트에서만 허용하세요. 폴더 접근·소스 전송 동의는 프로젝트마다
              따로 받습니다. 체크하지 않아도 대화와 명세 작성은 사용할 수
              있습니다.

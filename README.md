# CW_Handsoff_sys · Hands off System

Windows x64 · macOS arm64/x64 · v0.1.0

**만들고 싶은 앱을 설명하면, 역할을 맡은 AI들이 같은 작업 폴더에서 설계·구현·검증을 이어가는 PC용 작업 공간입니다.**

AI마다 같은 요구사항을 다시 설명하고, 한쪽에서 만든 코드를 다른 쪽으로 옮겨 붙이는 작업을 줄이려고 만들었습니다. Hands off의 **컨트롤 타워**에 요청을 보내면 내장 `/fun` 지침으로 기능과 완료 기준을 정리합니다. 그 기준을 기능 구현·UI·검토·테스트 담당에게 전달하고, 결과와 수정이 필요한 지점을 한 화면에서 확인합니다.

컨트롤 타워는 GPT·Claude·Gemini·Cursor 중에서 선택합니다. 사용할 AI가 하나뿐이라면 같은 계정을 여러 역할에 배치할 수 있고, 서로 다른 AI를 연결해 2~4개 패널로 나눠도 됩니다. 같은 계정을 여러 패널에서 쓰면 사용 한도도 공유합니다.

왼쪽에서 **폴더와 이전 대화**, 가운데에서 **컨트롤 타워 채팅**, 오른쪽에서 **AI별 진행 상황**을 봅니다. AI 로고를 누르면 담당 작업의 로그와 질문창이 열립니다. 자세한 흐름은 **Workflow 보기**, 시안 승인과 오류 안내는 상단 **종 아이콘**에서도 찾을 수 있습니다.

| --- | --- |
| 여러 AI에게 같은 설명을 반복하고 싶지 않을 때 | 역할을 한 번 배정하고 컨트롤 타워에 요청을 보냅니다. |
| 작업 중 AI 사용 한도가 소진될 때 | 연결된 팀에서 사용 가능한 AI를 찾아 같은 작업과 완료 기준을 전달합니다. 사용할 AI가 없으면 저장한 코드를 보존하고 멈춥니다. |
| 코드가 만들어지기 전에 화면을 보고 싶을 때 | UI 시안을 미리 보고 승인하거나, 바꾸고 싶은 부분을 채팅으로 요청합니다. |
| 테스트가 실제로 무엇을 확인했는지 알고 싶을 때 | 테스트별 통과·실패, 재현 절차, 담당 AI의 수정 과정을 봅니다. |
| AI 수정 전 상태로 돌아가고 싶을 때 | 체크포인트에서 되돌릴 파일을 확인하고 복원합니다. |
| 검증한 코드를 GitHub나 Vercel에 보내고 싶을 때 | 프로젝트별 대상과 계정을 확인한 뒤 푸시 또는 배포를 승인합니다. |

## 처음 실행하기

### 내 PC에 맞는 앱 받기

| 사용할 PC | 저장소 | 앱 다운로드 |
| --- | --- | --- |
| Windows x64 | [Windows 저장소](https://github.com/ccw00325-spec/Hands_off_system_window) | [Windows 실행 파일 받기](https://github.com/ccw00325-spec/Hands_off_system_window/actions/runs/42447573121) |
| MacBook · Apple Silicon / Intel | [Mac 저장소](https://github.com/ccw00325-spec/Hands_off_system_mac) | [Mac 패키지 받기](https://github.com/ccw00325-spec/Hands_off_system_mac/actions/runs/42447577278) |

다운로드 페이지에서 GitHub에 로그인하고 아래쪽 **Artifacts**를 펼치세요. Windows는 `Hands-off-Window-x64`, Mac은 CPU에 맞게 `Hands-off-Mac-arm64` 또는 `Hands-off-Mac-x64`를 선택합니다. 받은 압축 파일을 풀고 Windows는 `.exe`, Mac은 `.dmg` 또는 `.zip` 안의 앱을 실행하세요. Mac CPU는 **Apple 메뉴 → 이 Mac에 관하여**에서 확인할 수 있습니다. 파일 보관 기간은 30일입니다.

이 앱은 자신의 PC에 내려받아 실행합니다. OS별 준비 방법과 실행 시 보안 알림 안내는 [설치 안내](docs/platform-setup.md)에서 확인하세요.

### 필요한 도구 연결하기

앱 창을 여는 데 필요한 Electron 런타임은 패키지에 포함합니다. 첫 실행의 흰색 시작 창에서 **Git, Node.js 24+·npm, Docker와 선택한 AI CLI**를 점검합니다. 빠졌거나 오래된 도구가 있으면 준비 안내가 나타나고 **설치 안내 열기**를 누르면 공식 홈페이지가 열립니다. 설치 후 **설치 후 다시 확인**을 누르세요. 사용하지 않을 AI까지 모두 설치할 필요는 없습니다. 둘러보기를 먼저 할 수도 있습니다.

![처음 실행할 때 빠진 도구와 공식 설치 안내를 보여주는 실제 앱 화면](docs/screenshots/prerequisites.png)

설치 안내는 실행 파일·원격 스크립트를 몰래 다운로드하거나 실행하지 않습니다. Node.js 설치에는 npm이 함께 제공되며, GitHub 전송에는 Git이 필요합니다. Docker 격리를 사용하려면 엔진과 로컬 Linux 이미지도 준비해야 합니다. 설정의 **설치 도구 확인**에서 언제든 재검사할 수 있습니다.

우측 상단의 **필수 프로그램 설치**를 누르면 같은 설치 안내 창을 바로 엽니다. 도구별 필수·선택 여부와 설치 상태를 확인하고 공식 설치 안내로 이동할 수 있습니다.

**설치 안내를 열어 둔 채 설치하면 상태가 자동으로 바뀝니다.** 공식 안내를 연 뒤에는 ‘다운로드·설치 대기 중’, 검사할 때는 ‘설치·실행 확인 중’을 표시합니다. 화면이 보이는 동안 약 3초 간격으로 재검사하고, 다른 창에서 돌아오면 즉시 확인합니다. 실제 도구가 실행 가능한 것을 확인하면 **준비됨**으로 바뀌므로 매번 ‘설치 후 다시 확인’을 누를 필요가 없습니다. 확인이 끝나거나 안내를 닫으면 자동 검사를 멈춥니다. 이 확인은 AI 추론을 호출하지 않습니다.

외부 브라우저의 다운로드 진행률이나 설치 마법사의 내부 단계는 앱이 알 수 없습니다. 설치 파일만 내려받은 상태를 완료로 표시하지 않으며, 설치·버전·npm·Docker 엔진과 격리 이미지 등 필요한 조건을 실제로 검사합니다. **도구 설치 완료와 AI 계정 로그인은 별개**입니다. ‘준비됨’이어도 **계정 · 연결**에서 로그인이 필요할 수 있습니다. 사용자 지정 경로에 설치한 도구를 발견하지 못하면 PATH를 확인하고 앱을 다시 실행하세요.

각 도구의 **공식 안내 / 설치 안내 열기** 버튼 바로 위에는 **빨간 ‘필수’** 또는 **노란 ‘선택’** 표시가 작게 나옵니다. 필수 여부는 현재 선택한 AI·실행 방식을 기준으로 하며, 도구 아래에서 사용 목적을 확인할 수 있습니다. **필수 도구가 모두 ‘준비됨’이 되어야 AI 작업과 앱 제작을 시작할 수 있습니다.** 선택 도구가 없어도 시작할 수 있습니다. Docker 실행을 선택했다면 엔진과 지정한 로컬 이미지까지 준비해야 하며, PC 직접 실행으로 자동 전환하지 않습니다. Git은 코드 변경 이력을 기록하고 GitHub에 전송할 때 사용하는 로컬 도구입니다. GitHub 계정 로그인은 **보조 서비스 연결**에서 따로 진행하세요.

준비되지 않은 상태에서 작업을 요청하면 **설치 안내 팝업**이 열리고 우측에 **‘설치를 진행해주세요’** 알림과 빠진 프로그램 이름이 표시됩니다. 알림의 **필수 프로그램 설치** 버튼으로 다시 안내를 열 수 있습니다. 안내를 닫아도 작업·질문·재시도·테스트 재실행·시안 생성은 시작되지 않으며, 요청 내용은 입력란에 남습니다. 설치 전에도 설정·계정 연결·기존 기록 확인은 가능합니다. 실제 실행 가능 여부가 확인되면 **준비 완료 · 시작하기**로 바뀝니다. 창을 닫고 요청을 다시 보내세요. 설치를 마쳤다는 이유로 보관한 요청을 자동 전송하거나 AI 사용량을 소비하지 않습니다.

처음에는 **이미 사용하는 AI 하나를 두 패널에 배치**해 시작할 수 있습니다. 이미지 시안 생성에는 별도 개인 API 키가 필요하며, AI 구독과 이미지 API 과금은 각각의 공급자 조건을 따릅니다. Hands off를 실행한다고 다른 사람의 AI 계정이나 개발자 키가 제공되는 것은 아닙니다.

### 처음 하는 작업은 이 순서로 진행하세요

1. **새 프로젝트**에서 결과물을 저장할 빈 폴더를 고릅니다.
2. **계정 · 연결**에서 사용할 AI의 로그인 상태를 확인합니다.
3. **AI 역할 변경**에서 AI·모델·담당 역할을 고릅니다. 최소 2개, 최대 4개 패널을 사용합니다.
4. 컨트롤 타워에 원하는 기능을 적고 **작업 요청**을 누릅니다. `/fun` 질문 팝업이 뜨면 선택하거나 직접 답변하세요. 시안 승인을 켰다면 화면을 확인하고 `이대로 적용`을 보냅니다.
5. **Workflow 보기**에서 검증 결과를 확인합니다. GitHub나 Vercel 전송은 연결한 프로젝트의 대상과 승인 여부를 확인한 뒤 진행합니다.

프로젝트 파일은 선택한 폴더에 생성됩니다. 테스트 코드 실행에는 해당 폴더의 실행 승인이 별도로 필요합니다. AI의 완료 보고와 실제 테스트 통과는 구분해서 표시합니다.

앱이 열리면 첫 실행 안내가 나옵니다. **다음**으로 버튼의 쓰임을 살펴보거나 **건너뛰기**를 누를 수 있습니다. 상단의 **Hands off 가이드**에서 언제든 다시 열 수 있습니다.

앱이 열리기 전에는 화면 중앙의 **흰색 시작 창**에서 로그인 상태, AI 모델 목록, 프로젝트와 화면을 준비합니다. 캐릭터가 돌에 걸렸다가 박스를 주워 다시 걷는 동안 준비 단계가 진행되고, 바가 100%가 되면 작업 창이 열립니다. 진행률은 남은 시간의 예측치가 아닌 준비 단계 기준입니다.

![AI 모델 목록을 준비하는 실제 시작 창의 캐릭터 애니메이션 한 장면](docs/screenshots/startup.png)

시작할 때 준비한 목록을 **계정 · 연결**, **AI 역할 변경**, **컨트롤 타워의 모델 선택**에서 공유합니다. 목록을 불러오는 버튼을 누를 필요 없이 바로 선택하세요. 앱에서 로그인이나 GPT 실행 계정을 바꾸면 자동 갱신합니다. 미연결 AI는 로그인 필요로, 조회 실패는 확인 실패로 표시하며 앱을 무한히 기다리게 하지 않습니다. Claude는 공식 CLI 별칭을 표시합니다.

**Hands off 가이드**에는 실제 앱 화면을 넣은 8개 주제가 있습니다. AI·모델 선택 용어부터 시안 승인, 테스트와 뮤테이션 설정, 체크포인트 복원, 외부 서비스 전송까지 단계별로 설명합니다. 각 주제의 바로가기 버튼으로 해당 기능을 직접 열 수 있습니다.

![실제 화면과 모델·역할·자동 인계 설명을 포함한 앱 내 가이드](docs/screenshots/guide.png)

> 첫 작업 예시
>
> “1초부터 3,600초까지 설정할 수 있는 웹 타이머를 만들어줘. 시작·일시정지·초기화를 넣고, 일시정지하면 숫자가 멈추는지 테스트해줘. 마지막에 실행 방법도 알려줘.”

1. **새 프로젝트**를 눌러 빈 폴더를 고르고 접근 범위를 확인합니다. 생성된 파일은 이 폴더에 저장됩니다.
2. **계정 · 연결**에서 사용할 AI를 연결합니다. **AI 역할 변경**에서 작업 패널을 2개로 설정하고 같은 AI를 양쪽에 배치합니다. 첫 패널에 **컨트롤 타워**와 **테스트 설계·실행**, 두 번째 패널에 **기능 구현**과 **UI 구현·연결**을 맡긴 뒤 **역할 배치 저장**을 누릅니다.
3. 기본 시안은 **텍스트 구조안**이라 이미지 API 키가 없어도 됩니다. 테스트를 실행하려면 **Docker 격리**를 준비하고 **승인한 폴더의 테스트·검증 코드 실행 활성화**와 **현재 폴더 코드 실행 승인**을 확인하세요. 격리 모드는 Docker가 없을 때 PC에서 대신 실행하지 않습니다.
4. 컨트롤 타워에 예시를 붙여 넣고 **작업 요청**을 누릅니다. 오른쪽 AI 카드에서 진행 상태를 보고, **Workflow 보기**에서 테스트 결과를 확인합니다. 작업 보고에 나온 실행 방법으로 타이머를 열어 봅니다.

## 화면별로 익히기

아래는 예제 프로젝트로 실행한 앱 화면입니다. AI 연결·응답·사용 한도는 시연용 데이터이며 실제 연결한 계정에 따라 달라집니다. 시작 애니메이션과 타이머 이미지 시안은 이전 버전의 참고 화면이고, 새 작업은 기본적으로 텍스트 구조안부터 보여줍니다.

### 1. 작업 공간에서 요청 보내기

![가운데 컨트롤 타워 채팅과 오른쪽 세로 AI 카드 네 개, 실제 작업 기록과 대체 AI 연결 표시](docs/screenshots/workbench.png)

가운데 컨트롤 타워에 만들고 싶은 것을 적으세요. 대화 위 안내에는 시안 확인·테스트 결과처럼 **지금 할 일**이 나타납니다. 오른쪽 AI 카드에는 작업이 **대기 → 진행 중 → 구현 완료** 순서로 쌓이고, 전체 검증까지 통과하면 **완료**가 표시됩니다. 이전 작업은 접어서 볼 수 있습니다.

**작업 요청**을 눌렀는데 폴더·로그인·모델 선택이 빠져 있다면, 화면 위 안내가 필요한 설정과 이동 버튼을 보여줍니다. 예를 들어 Cursor 모델이 없으면 **AI 역할 변경**에서 해당 패널의 모델을 선택하도록 안내합니다. 안내는 클릭할 때마다 표시되고 각각 5초 뒤 닫힙니다. 준비가 끝나기 전에는 요청을 AI에 보내지 않습니다. 이미 전송 중일 때는 중복 요청을 막습니다.

곡선은 컨트롤 타워와 각 작업자를 연결합니다. 실제 업무 배정과 완료 보고 이벤트가 발생하면 박스를 든 캐릭터가 곡선을 따라 양방향으로 이동합니다. 컨트롤 타워 자신의 카드는 같은 대화를 여는 바로가기이므로 점선으로 구분합니다. 움직임은 설정에서 끌 수 있습니다.

| 어디를 누르나요? | 무엇을 하나요? |
| --- | --- |
| 왼쪽 **새 프로젝트** / 폴더 이름 | 새 작업 폴더를 선택하거나 기존 프로젝트로 전환합니다. 상단 **프로젝트 ≡**는 사이드바를 접고 펼칩니다. |
| 왼쪽 **대화 검색** / **새 대화** / **기록 관리** | 같은 프로젝트의 이전 대화를 찾거나 새 대화를 엽니다. 기록 관리에서는 대화를 보관·내보내기·삭제할 수 있습니다. |
| 가운데 **이름 편집** | 프로젝트 목록에 보이는 이름을 바꿉니다. |
| 오른쪽 **AI 로고** | 해당 AI의 실제 작업 로그와 개별 질문 입력창을 팝업으로 엽니다. 컨트롤 타워 로고는 가운데와 동일한 대화를 엽니다. |
| AI 로고 옆 **작업 이름** | 담당 AI 팝업에서 해당 작업의 변경 파일·완료 기준·제출 보고를 봅니다. |
| **Workflow 보기** | 명세·시안·작업 의존성·테스트·최종 검토를 그래프로 보고, 작업별 상세 내역을 확인합니다. |
| 가운데 **작업 요청** / **질문만** | 작업 요청은 구현을 시작합니다. 작업 중에는 질문 모드로 전환되며, 코드 변경 없이 설명을 요청할 수 있습니다. |
| 입력창 옆 **모델 선택** | 시작 시 준비한 실행 모델 목록에서 고릅니다. GPT 패널에서 `/model`을 입력해도 열 수 있습니다. |
| **작업 중지** | 현재 진행 중인 작업을 멈춥니다. 이미 적용한 변경은 체크포인트에서 확인할 수 있습니다. |
| 대화 제목 옆 **체크포인트** | 복원 가능한 변경과 영향을 받을 파일을 확인합니다. |
| 상단 **종 아이콘** | 알림 기록을 엽니다. 알림 위에 마우스를 올리면 휴지통이 나타나며, 오른쪽 아래 **전부 지우기**로 기록을 정리합니다. |

상단 사용량에는 지원되는 계정의 **5시간·주간 잔여 한도**가 `96%/43%`처럼 따로 표시되며 10초마다 갱신을 시도합니다. 공급자가 제공하지 않는 수치는 **조회 미지원**으로 표시합니다. **Workflow 보기 → 이번 작업 사용량**에서는 AI별 호출 수와 조회 가능한 토큰을 확인합니다.

![AI 로고나 작업을 눌러 여는 실제 작업 로그·변경 파일·개별 채팅 팝업](docs/screenshots/output.png)

팝업에서 질문하면 그 AI가 현재 프로젝트와 자신의 대화 기록을 바탕으로 답합니다. 개별 질문은 읽기 전용이며, 파일 변경은 컨트롤 타워의 **작업 요청**으로 보냅니다. 팝업 오른쪽 위 **×** 또는 **Esc**로 닫습니다.

![필요할 때 열어 작업 의존성·담당 AI·검증 결과를 확인하는 Workflow](docs/screenshots/workflow.png)

**완료 보고**는 담당 AI가 구현을 제출했다는 뜻입니다. **작업 완료**는 실행 검증과 최종 검토까지 통과했을 때 표시됩니다. 체크포인트를 복원하면 이전 검증 결과가 해제되어 다시 확인해야 합니다.

### 2. AI를 연결하고 역할 나누기

![AI 역할 변경 화면의 패널 개수, 공급자, 모델과 역할 체크박스](docs/screenshots/roles.png)

**계정 · 연결**에서 기존 로그인 상태를 확인하고, **AI 역할 변경**에서 실제 작업에 쓸 패널과 역할을 정합니다.

| 연결할 AI | 사용 방법 |
| --- | --- |
| GPT | 공식 Codex CLI의 ChatGPT 로그인 상태를 확인합니다. |
| Claude | 공식 Claude Code에 로그인합니다. |
| Grok | Cursor Agent CLI에 로그인하고, 계정에서 제공되는 Grok 모델을 선택합니다. |
| Gemini | Gemini CLI에서 Google 계정으로 로그인합니다. |

**작업 패널 수**는 2~4개로 정할 수 있습니다. 01번은 **컨트롤 타워**에 고정되며 AI는 바꿀 수 있습니다. **기능 구현**과 **UI 구현·연결**은 각각 한 패널만 맡습니다. **디버깅**, **코드 검토**, **테스트 설계·실행**은 중복 배정할 수 있습니다. 담당을 옮길 때는 기존 체크를 해제한 뒤 다른 패널에서 선택하세요.

패널 수를 2개·4개로 바꾸면 **기능·UI 담당이 빠지지 않도록 배분**하고, 모든 패널의 **디버깅·코드 검토·테스트 설계·실행**을 기본 선택합니다. 기능·UI 구현은 각각 한 담당을 유지합니다. Cursor에 UI를 자동으로 몰아주지 않으며, Cursor의 UI 체크를 직접 켜거나 기존 UI 담당을 Cursor로 바꾸면 **취소 / UI 역할 선택** 경고에서 의사를 확인합니다. 선택한 역할은 저장 전에 조정할 수 있습니다.

처음 3개 패널로 시작할 때의 기본 배치는 다음과 같습니다. 패널 수를 바꾸면 위에서 설명한 공통 검증 역할도 채워집니다.

| 기본 AI | 기본 업무 |
| --- | --- |
| GPT | 컨트롤 타워 + 디버깅 + 코드 검토 + 테스트 설계·실행 |
| Grok · Cursor | 기능 구현 + 디버깅 + 코드 검토 |
| Claude | UI 구현·연결 + 코드 검토 |

모델 목록은 **시작 창에서 미리 준비**합니다. **AI 역할 변경**을 열거나 사용할 AI를 바꾸면 준비된 목록을 즉시 표시합니다. **GPT 모델 선택**처럼 AI 이름을 표시하므로 실행할 모델을 바로 고를 수 있습니다. GPT·Claude의 **자동 선택**은 해당 계정의 현재 실행 설정을 따릅니다. Cursor·Gemini는 목록에서 모델을 선택하며, 이 앱에 저장한 모델이 목록에 있으면 먼저 표시합니다. 목록이 없거나 조회가 실패하면 연결 확인 안내를 표시합니다.

같은 계정을 여러 패널에 배치하면 사용 한도도 공유합니다. 실행 중 배치를 바꾸면 다음 작업부터 적용되며, 진행 중인 작업은 시작할 때의 배치를 유지합니다.

### 디버깅·코드 검토 결과를 순서대로 확인하기

구현과 실행 테스트 뒤에는 **Grok·Cursor → Gemini → Claude → GPT** 순서로 선택된 검토 담당에게 결과를 전달합니다. **컨트롤 타워는 어떤 AI를 선택해도 마지막**입니다. 예를 들어 Claude가 컨트롤 타워라면 작업자 GPT가 먼저 확인하고 Claude가 최종 검토합니다. 연결하지 않았거나 검토 역할을 선택하지 않은 작업자를 임의로 추가하지 않습니다.

![네 패널이 테스트 결과와 앞선 의견을 받아 순서대로 확인한 Workflow 예제](docs/screenshots/review-chain.png)

**Workflow 보기 → 순차 디버깅·코드 검토**에서 **대기 → 검토 중 → OK** 흐름을 봅니다. 각 AI에는 같은 파일 버전의 테스트 결과와 앞선 검토 의견을 전달합니다. 오른쪽 AI 카드에서도 자기 차례와 결과를 확인하고 로고를 눌러 상세 로그를 읽을 수 있습니다.

수정이 필요한 항목이 나오면 다음 검토는 기다립니다. 담당 AI가 고친 뒤 테스트를 다시 실행하고 새 파일 버전으로 순차 검토를 다시 시작합니다. 실제 디버깅 코드 변경 작업이 여러 패널에 배정된 경우에도 같은 순서를 의존 관계에 반영합니다. 테스트 실행이 보류되거나 실패했는데 AI가 `OK`라고 했다는 이유로 전체 완료가 되지는 않습니다.

### 사용 한도가 소진될 때 대체 AI로 이어가기

대체 AI를 따로 지정하지 않아도 **현재 팀에 연결된 AI**에서 이어받을 대상을 찾습니다. 담당 역할, 확인 가능한 잔여 한도와 로그인·모델 준비 상태를 고려합니다. 예를 들어 GPT 40%, Cursor 소진, Claude 10%이고 기능 구현을 이어받을 때 역할 적합도가 같으면 GPT를 우선 확인합니다.

최근 2분 안에 확인한 공식 잔여 한도가 **5% 이하**이면 다음 요청 전에 여유 있는 팀 AI를 찾습니다. Cursor처럼 잔여 비율을 제공하지 않는 연결은 추정하지 않고 실제 한도 소진 오류가 있을 때 전환합니다. **대체 AI 우선순위 (선택)**를 펼치면 먼저 확인할 AI와 모델을 직접 정할 수도 있습니다.

![기본 Gemini와 대체 Claude를 선택한 역할 설정 항목](docs/screenshots/fallback-settings.png)

- 작업 ID·역할·명세·완료 기준·전달받은 소스와 대화 맥락을 유지합니다. 공급자 내부의 비공개 세션 자체를 옮기는 방식은 아닙니다.
- 대체 AI의 기존 로그인과 모델 연결을 확인한 뒤 실행합니다. 사용할 수 없으면 다른 팀 AI를 확인하고, 모두 사용할 수 없으면 저장된 코드를 보존한 채 사용자 확인 상태로 멈춥니다.
- 전환되면 해당 카드의 **로고·AI 이름·모델·대체 연결 표시**가 바뀝니다. 완료 후 개별 질문도 같은 대체 AI가 받으며, 새 작업은 설정한 기본 AI부터 시작합니다.
- 일시적인 요청 속도 제한·네트워크 오류·인증 만료·컨텍스트 길이 초과를 일반적인 한도 소진으로 간주해 전환하지 않습니다. 인식하지 못하는 오류는 로그와 함께 멈춥니다.
- 실패한 기본 호출과 대체 호출을 모두 호출 한도에 포함합니다. 같은 공급자의 다른 모델도 계정 한도를 공유할 수 있습니다. GPT 실행의 로그인/API 방식을 임의로 바꾸지 않으며 이미지 API 연결은 별개입니다.
- Cursor가 **UI 구현·연결**을 맡게 되면 앱의 역할 권장 설정에 따라 **취소 / 이번 작업에서 진행**을 먼저 표시합니다. 확인 후 이번 작업을 맡길지 선택하세요. 이 안내는 모든 Cursor 모델의 성능 순위를 뜻하지 않습니다.
- 응답 도중 끊긴 비공개 내부 세션이나 저장되지 않은 미완성 응답은 옮길 수 없습니다. 마지막 저장 코드와 명세·완료 기준을 같은 작업 요청으로 전달해 다시 이어갑니다.

이어받은 AI는 같은 명세·완료 기준과 저장된 코드, 남은 오류를 확인하고 작업합니다. AI 서비스 내부의 비공개 기억이나 저장되지 않은 응답까지 복원하는 것은 아닙니다.

![Gemini 한도 소진 후 Claude로 전환된 실제 앱의 알림 기록과 개별 삭제 버튼](docs/screenshots/notifications.png)

화면 알림은 약 10초 뒤 사라지고 **종 아이콘**에 기록으로 남습니다. 알림을 삭제해도 작업·대화·테스트 결과는 삭제되지 않습니다. 기록은 현재 OS 사용자의 앱 프로필에 최대 200개까지 보관합니다.

### /fun으로 빠진 조건 확인하기

채팅창 아래 **/fun 요구사항 확인**은 기본적으로 켜져 있습니다. 컨트롤 타워가 요청에서 조건·입력·결과나 완료 기준의 빈칸을 발견하면 구현을 멈추고 팝업으로 질문합니다.

`/fun`을 켠 작업에서는 설정의 **무질문 위임**보다 빈칸 확인을 우선합니다. 답을 미뤘다는 이유로 AI가 조건을 정해 구현하지 않습니다.

![선택지와 직접 입력으로 미정 조건에 답하는 /fun 질문 팝업](docs/screenshots/fun-questions.png)

- 원하는 선택지를 고르세요. 맞는 답이 없다면 각 질문의 맨 아래 **위 선택지와 다르다면 직접 입력**을 선택하고 내용을 적습니다. 자동으로 선택된 답은 없습니다.
- **답변 보내고 이어서 진행**을 누르면 원래 요청과 답변을 같은 작업에 반영합니다. 답변은 대화에도 남습니다.
- **나중에 답변**, **×**, **Esc**로 닫아도 구현을 임의로 시작하지 않습니다. 채팅창 아래 또는 종 알림의 **질문에 답변하기**로 다시 여세요. 제출한 답변과 대기 질문은 앱을 다시 켜도 확인할 수 있습니다.
- 백그라운드에서 실행 중이어도 새 질문에는 Windows 알림과 기본 알림 소리를 요청합니다. 알림을 클릭하면 앱과 해당 대화가 열립니다. 표시·소리는 Windows 알림 권한, 음량과 방해 금지 설정을 따릅니다. Mac의 시스템 알림은 OS 권한·서명 상태에 따라 제한될 수 있으며 앱 안의 팝업과 종 알림은 계속 사용할 수 있습니다.

질문 없이 바로 계획을 진행하고 싶다면 **/mut 뮤테이션 테스트** 옆의 **/fun 요구사항 확인** 체크를 해제한 뒤 새 작업을 요청하세요. 선택은 이 컴퓨터의 앱 설정에 저장되어 다음 실행에도 유지되며 새 작업부터 적용됩니다. 스킬을 꺼도 폴더 접근·코드 실행·위험한 작업의 승인 절차는 유지합니다.

### 3. UI 시안을 확인하고 수정하기

![UI 시안 편집 입력란, 타이머 미리보기, 모델 변경과 PNG 내보내기](docs/screenshots/design.png)

UI 작업이 포함되고 시안 승인 설정이 켜져 있으면, 기본적으로 **이미지 API를 호출하지 않는 텍스트 구조안**을 보여주고 승인을 기다립니다. 박스를 든 캐릭터가 왼쪽 **UI 시안**으로 안내합니다. 구조안은 설계의 화면 구성·상태·스타일과 수정 요청을 읽는 미리보기이며, 완성 화면 이미지라고 표시하지 않습니다.

![이미지 API를 쓰지 않고 화면 구성과 상태를 확인하는 실제 텍스트 구조안](docs/screenshots/layout-preview.png)

- 왼쪽 **UI 시안**, 컨트롤 타워의 안내 버튼, 종 알림의 **시안 확인** 중 편한 곳을 누릅니다. Workflow의 **UI 시안** 노드에서도 열 수 있습니다.
- 구조만 확인하려면 **텍스트 구조안에 수정 요청 반영**을 사용합니다. 이미지 API 호출은 없습니다.
- 시각적인 시안이 필요할 때 **모델 변경**에서 GPT Image 또는 Gemini Flash Image를 선택하고 **시안 생성 · API 사용량 발생**을 누릅니다. 이때만 이미지 API 키와 비용이 필요합니다. 설정에서 기본 형식을 이미지로 직접 바꿀 수도 있습니다.
- 입력란에 “시간 숫자를 더 크게”처럼 바꿀 내용을 적고 **시안 생성**을 누릅니다. 컨트롤 타워에서도 `시안 수정: 시간 숫자를 더 크게`라고 보낼 수 있습니다.
- 마음에 들면 **컨트롤 타워로 돌아가기**를 눌러 `이대로 적용`을 보냅니다. 파일로 보관할 때는 **PNG 내보내기**를 사용합니다.

**승인한 이미지와 구현 화면도 따로 비교합니다.** 기능 테스트를 통과하면 같은 화면 크기로 실제 앱을 캡처하고, UI를 구현한 역할의 AI가 시안과 나란히 보며 **배치·색상·글꼴·간격·크기·아이콘**을 확인합니다. 차이가 있으면 원래 UI 담당에게 구체적인 수정 사항을 돌려보내고, 수정 후 기능 테스트와 이미지 비교를 다시 실행합니다. 기존 테스트나 승인 시안을 바꿔 통과시키지 않습니다. 보정은 설정한 자동 수정 횟수와 호출 한도 안에서 진행합니다.

**Workflow → 시안·구현 비교** 또는 **UI 시안 → 시안·구현 비교**에서 원본 시안·실제 화면·항목별 근거를 함께 봅니다. **기능 검증 통과**와 **AI 기준 일치**는 다른 결과입니다. 파일이 바뀌거나 체크포인트를 복원하면 이전 판정은 다시 확인해야 합니다. 설정의 **이미지 시안과 구현 화면 자동 비교·보정**에서 다음 작업의 기본 사용 여부를 바꿉니다.

현재 자동 캡처는 **루트의 정적 `index.html`과 로컬 리소스로 실행되는 화면**을 지원합니다. 빌드·개발 서버가 필요한 앱, 이미지 입력을 지원하지 않는 연결, 화면 오류나 권한 부족은 ‘확인 필요’로 멈추며 일치로 처리하지 않습니다. Docker 테스트 동의는 PC의 브라우저 실행 동의와 다릅니다. 필요하면 **다시 비교**에서 해당 폴더의 브라우저 미리보기를 별도로 허용하며, 이때 캡처가 UI 담당 AI에 전달된다는 안내가 나옵니다. Docker 테스트 설정은 그대로 유지됩니다.

이미지 임베딩의 유사도 점수만으로 통과시키지 않습니다. AI가 실제 화면 차이를 검토하지만 **픽셀 단위 일치나 모든 상태·기기의 디자인 품질을 보장하는 검사는 아닙니다**. 비교 화면에서 근거를 확인하고, 버튼 동작과 모바일·접근성은 기능 테스트로 함께 검사하세요. [비교 범위와 권한 안내](docs/visual-review.md)

### 4. 테스트 결과를 읽고 필요하면 복원하기

![테스트 보고서에서 테스트별 결과와 재현 절차를 확인하는 화면](docs/screenshots/test-report.png)

**테스트 설계·실행** 역할을 배정하면 요구사항을 실제 테스트 코드와 연결하고 재현 절차를 남깁니다. 실행 권한을 승인한 폴더에서는 Node 내장 테스트나 지정한 npm 스크립트로 결과를 확인합니다. 실패 항목과 담당 AI는 **Workflow 보기**에서 확인합니다. 컨트롤 타워는 **설정 → 자동 수정 최대 횟수** 안에서 수정과 재실행을 요청합니다. 같은 실패가 반복되거나 테스트 자체에 문제가 있다고 판단되면 사용자 확인 상태로 멈춥니다. 실행 권한이 필요하면 대화 위 안내 버튼으로 설정을 엽니다.

수정된 코드의 **기존 테스트는 그대로 다시 실행**합니다. UI나 기능 코드가 바뀌었다는 이유만으로 통과한 테스트를 AI에게 다시 작성시키지 않습니다. 검토에서 테스트 누락이나 뮤테이션 검증의 허점을 구체적으로 배정한 경우에는 해당 테스트 담당에게 보강을 요청합니다. 실행과 AI의 코드 작성은 별도 단계이므로 불필요한 재작성 호출을 줄이면서 검증은 유지합니다.

- **결과·재현 절차**에서 각 테스트의 결과와 실행 명령을 확인합니다. 필요한 경우 **테스트 다시 실행**을 누릅니다. 통과하면 새 결과를 AI 검토 담당에게 전달해 순차 검토도 진행합니다.
- AI 연결이나 구현 도중 중단되면 **문제 작업 출력 보기**로 담당 AI의 로그와 변경 내역을 확인합니다.
- **체크포인트**에서 복원 지점과 영향을 받을 파일을 미리 봅니다. 사용자가 이후 수정한 파일과 충돌하면 복원을 멈춥니다.
- 기본 완료 기준은 계획한 일반 테스트 실행과 검토입니다. 패키지를 자동 설치하지 않으며, Node 내장 테스트나 프로젝트의 npm 테스트 스크립트를 사용합니다.
- 채팅창 아래 **/mut 뮤테이션 테스트**는 기본적으로 꺼져 있습니다. StrykerJS와 프로젝트의 `test:mutation`·JSON 보고 설정을 갖춘 경우 선택하세요. 선택했는데 미설정이면 통과로 표시하지 않습니다. 자주 사용하는 프로젝트라면 설정에서 새 작업의 기본 선택을 켤 수 있습니다.

## 실행 권한과 데이터

프로젝트 파일은 선택한 폴더에 저장됩니다. AI가 작업에 필요한 소스를 읽거나 전달하는 범위는 폴더 연결 시 확인할 수 있습니다. 앱에 등록한 API 키는 OS 보안 저장소로 암호화하고, 공식 CLI 로그인은 현재 OS 사용자의 세션을 재사용합니다.

테스트·빌드는 기본적으로 **Docker 격리 환경**에서 실행합니다. 프로젝트의 비밀 파일과 로그인 정보는 전달하지 않고, 원본 파일을 직접 수정하지 않는 복사본으로 검사합니다. Docker나 필요한 이미지가 준비되지 않으면 **설정 필요**로 멈춥니다. [Docker 준비 방법](docs/platform-setup.md#docker-실행-준비)을 따라 설치한 뒤 다시 실행하세요. 프로젝트 라이브러리가 필요하면 해당 의존성을 준비한 이미지도 필요합니다.

설정에서 **현재 PC**를 선택하면 별도 경고·동의를 받습니다. 이 방식은 PC 사용자 권한으로 코드를 실행하므로 신뢰하는 폴더에만 사용하세요. Docker 격리는 프로젝트 테스트·빌드에 적용되며 앱과 공식 로그인 자체는 PC에서 실행합니다.

대체 AI를 설정하면 동일한 작업 자료가 선택한 다른 공급자에게 전달될 수 있습니다. 공유가 허용되는 프로젝트에서 연결하세요. 저장소와 배포 파일에는 개발자의 로그인 프로필·키 저장소를 포함하지 않습니다. 연결 상태는 실행한 컴퓨터의 OS 사용자 환경에서 새로 확인합니다.

## 사용량과 자동 작업 제한 설정하기

**설정**에서 작업별 호출 수, 하루 전체 호출 수, 하루 이미지 생성 횟수와 자동 수정 최대 횟수를 정할 수 있습니다. 한도에 도달하면 새 요청을 멈추므로, 계속 진행하려면 현재 사용량을 확인하고 설정을 변경하세요.

- 질문과 대체 AI 호출도 횟수에 포함합니다. 일일 호출 제한은 UTC 기준이며 앱을 다시 켜도 유지됩니다.
- 일일 제한을 바꾸면 진행 중인 작업의 다음 호출부터 적용합니다.
- API 금액 예산은 설정 단가와 최대 응답 크기로 미리 예약합니다. 실제 청구액의 보장된 상한은 아니며, 다른 앱이나 PC에서 쓴 비용까지 제한하지 않습니다.
- 비용을 계산할 수 없는 이미지 요청은 금액 예산이 켜져 있으면 차단될 수 있습니다. CLI 구독의 잔여 한도와 API 비용은 별도로 확인하세요.

## 자주 묻는 질문

### AI 하나만 유료로 쓰고 있어도 되나요?

네. 같은 AI 계정을 2개 이상의 패널에 배치하고 역할을 나누면 됩니다. 단, 패널 수만큼 계정의 사용 한도가 늘어나는 것은 아닙니다.

### 이미지 API 키 없이도 시작할 수 있나요?

네. 기본 텍스트 구조안으로 화면 구성을 확인하고 구현을 진행할 수 있습니다. 이미지 시안을 직접 생성할 때 별도 개인 API 키가 필요합니다.

### AI가 완료했다고 했는데 왜 작업은 끝나지 않나요?

구현 제출과 최종 완료는 구분됩니다. **Workflow 보기**에서 실패한 테스트, 미해결 검토 의견, 실행 승인이나 설치가 필요한 항목을 확인하세요. AI의 보고만으로 오류가 없다고 판단하지 않습니다.

### 작업이 중단되면 무엇부터 확인하나요?

대화 위 안내와 **종 아이콘**을 확인한 뒤 **문제 작업 출력 보기**로 담당 AI의 로그를 여세요. 테스트는 **테스트 다시 실행**, 전송 실패는 해당 서비스의 재시도로 이어갈 수 있습니다. 원하지 않는 코드 변경은 **체크포인트**에서 파일을 확인한 뒤 복원하세요.

### 이전 대화나 작업 기록을 정리할 수 있나요?

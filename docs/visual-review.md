# 시안과 실제 구현 비교

이 검사는 버튼이 작동하는지 확인하는 기능 테스트와 별개입니다. 승인한 이미지가 있는 UI 작업에 기본 적용하며, 텍스트 구조안에는 이미지 일치 판정을 만들지 않습니다.

## 실행 순서

1. 기능·UI 담당이 구현하고 기존 기능 테스트를 실행합니다.
2. 기능 테스트를 통과하면 시안의 가로·세로 크기로 실제 화면을 캡처합니다.
3. UI를 구현한 역할의 AI에 시안과 구현을 나란히 붙인 PNG를 전달합니다. 같은 공급자가 한도 때문에 교체됐다면 해당 역할의 현재 연결을 사용합니다.
4. 배치·색상·글꼴·간격·크기·아이콘을 각각 비교하고, 차이가 있으면 위치·기대 모습·현재 모습을 기록합니다.
5. 차이는 원래 UI 작업의 허용된 파일에만 배정합니다. 승인 이미지, 테스트, 패키지 설정이나 다른 역할의 코드를 바꿔 통과시킬 수 없습니다.
6. UI 보정 후 기존 기능 테스트와 새 캡처 비교를 반복합니다. 최종 코드 검토도 통과해야 전체 완료입니다.

자동 수정 횟수와 작업·일일 호출 한도를 공유합니다. 한도에 도달하면 차이를 남긴 채 사용자 확인 상태로 멈춥니다. 이미지가 완전히 같은 경우 이전 판정을 재사용해 중복 AI 호출을 줄이며, 직접 ‘다시 비교’를 누르면 새 AI 검토를 요청합니다.

## 확인하는 곳

Workflow와 UI 시안 화면의 **시안·구현 비교**에서 두 이미지와 여섯 항목의 근거를 봅니다. ‘기능 검증 · 통과’와 ‘AI 기준 일치’를 구분합니다. 소스·시안·리소스가 바뀌거나 파일을 복원하면 이전 판정을 현재 작업에 적용하지 않습니다.

## 현재 지원 범위와 권한

자동 캡처는 정적 `index.html` 또는 승인한 로컬 개발 서버를 지원합니다. Vite·Next dev·React Scripts 스크립트를 감지하며, 사용자 지정 npm 작업과 로컬 URL로 덮어쓸 수 있습니다. 새 스크립트·주소·실행 위치는 프로젝트별 확인 창에서 승인해야 합니다. PNG 시안은 가로 320~1920px, 세로 240~2160px, 총 약 314만 픽셀 이하를 지원합니다.

설정의 **개발 서버·상태별 프리뷰 설정**에서 경로·뷰포트·CSS 선택자·click/fill/select 동작을 최대 6개 지정합니다. 기본은 모바일·태블릿이고 데스크톱은 승인 시안 크기로 캡처합니다. 모달을 연 뒤 특정 컴포넌트만 캡처할 수 있습니다. 화면 상태의 캡처를 사용자가 별도로 회귀 기준으로 승인하면 같은 시안·뷰포트·동작에서 픽셀 변화량과 DOM 배치·스타일 차이를 계산합니다. 변화율은 디자인 품질이나 유사도 점수가 아닙니다. 기준이 없는 상태는 기준 없음으로 남깁니다.

프로젝트 설정 또는 `package.json`의 `handsoff.preview`에서도 지정할 수 있습니다. 파일에 설정했다고 실행 권한까지 생기지는 않습니다. 예:

```json
{
  "handsoff": {
    "preview": {
      "mode": "script",
      "script": "preview:app",
      "cleanupScript": "preview:stop",
      "url": "http://127.0.0.1:5173/dashboard",
      "profiles": [{"id":"modal","path":"/dashboard","width":768,"height":1024,"selector":"#details","actions":[{"type":"click","selector":"#open-details"}]}]
    }
  }
}
```

미리보기는 비밀 파일을 제외한 임시 복사본으로 실행합니다. Windows Next의 드라이브 간 경로 문제를 피하려고 현재 폴더의 .control-tower/previews 아래에 실행 중에만 관리용 임시 폴더를 만들며 종료 후 지웁니다. 응답은 파일당 8MiB·전체 32MiB로 제한합니다. Next 등 개발 소스맵이 큰 프로젝트는 프리뷰용 webpack 설정에서 devtool을 끄거나 빌드한 프리뷰 작업을 사용하세요. 용량 초과를 정상 캡처로 처리하지 않습니다. 의존성을 자동 설치하지 않습니다. PC 실행은 해당 프로젝트 안에 준비된 실제 `node_modules`를 사용합니다. 외부 패키지로 연결된 모노레포 의존성은 자동 연결하지 않으므로 프리뷰용 독립 패키지나 준비된 Docker 이미지를 사용하세요. Next 16 이상 기본 dev 명령은 격리 복사본과 호환되는 Webpack으로 실행하며 명시한 Turbopack 설정을 임의로 바꾸지 않습니다.

Docker는 의존성이 `/opt/node_modules`에 준비된 로컬 Linux 이미지가 필요합니다. 자체 내부 브리지와 PC 루프백 포트만 사용하고, 외부 네트워크·Docker 소켓·자격증명은 전달하지 않습니다. Compose 등 사용자 지정 PC 서버는 foreground 실행과 정리 npm 작업이 필요합니다. 종료 시 그 작업을 실행하며 정리에 실패하면 로그와 임시 폴더를 남기고 사용자 정리를 요청합니다. 이미 켜진 서버에 연결하는 external 모드는 현재 소스와 연결을 증명할 수 없어 캡처를 남겨도 자동 일치 완료로 처리하지 않습니다.

브라우저 프록시는 읽기 전용 GET/HEAD만 전달하고 인증 헤더·쿠키·외부 API·CDN·실제 DB 계정을 전달하지 않습니다. 로그인 뒤 화면·POST 요청·백엔드 데이터가 필요한 앱에는 별도의 프리뷰용 데이터와 읽기 전용 경로를 준비하세요. 프레임워크의 HMR 소켓은 승인한 개발 서버의 루프백 주소로만 제한됩니다.

렌더링이 실패하면 콘솔·네트워크 실패·프로세스 로그와 DOM 텍스트를 비밀값 마스킹 후 UI 담당 AI에게 전달합니다. 구체적인 UI 코드 오류만 기존 수정·호출 한도 안에서 보정하고 재캡처합니다. 설치·권한·의존성 문제는 환경 확인으로 남기며 권한을 약화해 우회하지 않습니다.

브라우저는 Node·preload·앱 IPC 없이 별도 샌드박스와 임시 세션으로 열며, 외부 통신·다운로드·새 창·파일 이동을 막습니다. 리소스는 승인 폴더에서만 읽고 요청 수·용량·실행 시간을 제한합니다. 비밀값을 발견하면 AI로 보내지 않습니다. 이는 모든 취약점이 없다는 보장은 아닙니다. 구현 기준은 Electron 공식 [프로세스 샌드박스](https://www.electronjs.org/docs/latest/tutorial/sandbox)와 [보안 권고](https://www.electronjs.org/docs/latest/tutorial/security)입니다.

현재 폴더의 PC 실행에 동의했다면 해당 경계 안에서 미리보기를 사용합니다. Docker 테스트 동의만 있다면 별도의 브라우저 실행 동의가 필요합니다. ‘권한 확인 후 다시 비교’에서 캡처와 화면 정보가 UI 담당 AI에 전달됨을 확인하고 허용할 수 있습니다. 권한은 OS 사용자·현재 폴더 승인에 묶이며 추가 허용은 비교 창에서 해제합니다. Docker 테스트 설정을 PC 실행으로 바꾸지 않습니다.

이미지 입력 비용을 계산할 수 없는 API 연결에 하드 예산을 설정한 경우 기존 비용 정책에 따라 호출이 보류될 수 있습니다. 구독 CLI도 공급자 사용 한도를 소비합니다.

## 해석할 때 주의할 점

임베딩 유사도나 임의의 일치율로 통과시키지 않습니다. 실제 화면을 AI가 검토하지만 판정에는 오차가 있습니다. ‘AI 기준 일치’는 픽셀 완전 일치나 모든 화면 상태·모바일·접근성 검증을 뜻하지 않습니다. 중요한 화면은 사람이 비교 근거를 확인하고, 동작은 기능 테스트로 확인해야 합니다.

Claude 이미지 연결은 공식 CLI의 `stream-json` 입출력과 최종 결과 이벤트를 사용합니다. 초기화나 중간 응답을 최종 판정으로 취급하지 않습니다. 관련 규격은 [Claude CLI 안내](https://code.claude.com/docs/en/cli-reference)에서 확인할 수 있습니다.
